Live Lua automation

A planned replay and recording workflow built around the existing local CE bridge.

Existing: local input/telemetry bridge and guarded experiments. Planned: portable adapters, reusable replay recipes and a live control panel.

The intended workflow

  1. Observe

    Resolve the game-specific locator and read position, room, angle and animation. Confirm the expected starting state.

  2. Replay

    Execute a bounded sequence of keyboard inputs. Wait for each acknowledgement and check the resulting state.

  3. Verify and pause

    Stop at a meaningful checkpoint: pickup count, crouch transition or upper landing. Unexpected state or focus loss pauses the run.

  4. Record

    Capture the agreed demonstration only after a successful rehearsal. Associate video checkpoints with telemetry events.

Keep three responsibilities separate

Game adapter

TR1R, TR2R or TR3R identity checks, locator, offsets and state names. Only TR3R has measured values in this draft.

Replay recipe

Application-specific prerequisites, inputs, expected checkpoints and stopping conditions. No hidden position or animation writes in a keyboard-only recipe.

Local runner

Owns one command at a time, validates acknowledgements, logs evidence and coordinates recording. The planned panel will expose start, pause and stop.

Existing file protocol

session|unique-id|COMMAND|argument

Protocol examples:
session|unique-id|READ|0
session|unique-id|BUFFERDUCK|180

session and unique-id above are placeholders, not ready-to-run commands.

  • ce_bridge_command.txt: a command tied to the current session.
  • ce_bridge_status.txt: matching acknowledgement; states include RUNNING, DONE, REJECTED, PAUSED and STOPPED.
  • ce_bridge_stop.txt: session-tagged stop request.

The client waits for DONE before replacing a command. A load can invalidate the locator. Do not silently resume a run against an unverified pointer.

Before a public automation package

  • Remove machine-specific paths and define explicit per-game configuration.
  • Record executable/module versions or hashes with offset verification.
  • Integrate the approved Nevada Setup into the runner and independently validate the complete replay. Manual approval does not validate the older Lua runner.
  • Keep research writes separate from input-only replay mode.
  • Document the recording backend, stop behavior and manual save/load boundaries.

This website is static documentation. It does not connect to Cheat Engine or control the game. No portable Lua package or live web panel is included yet.
